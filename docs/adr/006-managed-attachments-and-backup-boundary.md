# ADR-006: 托管附件、补偿清理与备份边界

- Status: Accepted
- Date: 2026-09-21
- Owners: ScheduleAssistant integration owner
- Related task(s): DEV-070；DEV-020；DEV-021；DEV-030

## Context

FR-ATT-001～006 要求附件内容留在应用托管目录，SQLite 只保存元数据；导入过程还必须能处理源文件消失、数据库提交失败、进程中断和任务删除后的文件清理。文件系统和数据库不是同一个原子资源，若没有明确边界，容易出现数据库有记录但没有文件、磁盘有副本但没有记录，或误删用户的源文件。

同时，附件可能包含任务正文之外的用户资料。日志不能泄露任务正文、源文件完整路径或附件内容；备份也不能把“数据库备份成功”误解为“附件内容已经备份”。

## Decision

### 托管副本

- `IAttachmentUseCases` 是独立的 Application 用例边界；`ITaskUseCases` 不增加附件方法。
- `IAttachmentStore` 是唯一的文件存储端口。Presentation 只调用 Application 用例和 UI 交互端口，不访问 SQLite、文件系统或 Win32。
- 导入使用 `IAppPaths.AttachmentsDirectory` 下的相对托管路径：`{task-id}/{attachment-id}_{safe-file-name}`。显示名保留在元数据中，托管文件名经过 Windows 文件名清理；所有读、写、删除和定位操作都再次验证相对路径、根目录和链接目标。
- 导入先写同一任务目录中的临时文件，同时计算大小和 SHA-256；关闭并刷新临时文件后再在同一目录内原子移动到最终路径，最后在 SQLite 事务中提交元数据。源文件只读，永远不删除或移动。

### 补偿与任务删除

- 文件已提交而元数据事务失败时，Application 尝试删除最终文件；补偿删除失败则写入现有 `cleanup_queue`，不把数据库错误伪装成成功。
- 任务删除沿用提交后的 `TaskDeleted` 事件。事件处理只清理该任务附件目录，不回滚已经成功的任务删除；清理失败写入 `cleanup_queue`。
- 单附件移除先提交元数据删除，再删除托管文件；文件删除失败返回非阻塞警告并入队。源文件不参与任何删除路径。
- 启动时只读取有限数量的清理队列项目，每个项目做有限次数重试，然后做一次托管目录与元数据的孤儿诊断；不注册计时器、不持续扫描、不自动删除未识别的孤儿文件。诊断和日志只使用托管相对路径或计数，不输出源文件完整路径、任务正文或文件内容。

### 备份边界

- DEV-070 不实现备份，也不修改既有迁移。SQLite 备份只覆盖附件元数据，不能单独证明附件字节已备份。
- 后续备份能力必须把 SQLite 数据库与 `attachments` 托管目录作为同一份应用数据范围，采用一致性快照或明确的停写/复制协议；恢复必须保留任务目录结构和托管相对路径。
- 用户在导入时选择的源文件属于用户自己的原始数据，不属于 ScheduleAssistant 的删除、迁移或备份责任；后续备份适配器也不得把源文件路径当作托管内容来源。
- 恢复后若元数据与托管文件不一致，启动诊断报告孤儿/缺失状态，由后续恢复工具或用户决定处理，不静默删除文件。

## Alternatives considered

- 把二进制内容存入 SQLite：会放大数据库、备份和事务负担，且不符合 FR-ATT-001 的元数据-only 约束；拒绝。
- 直接把源文件路径写入数据库并打开源文件：源文件可能被移动或删除，也会把外部目录生命周期带入应用；拒绝。
- 任务事务内同步复制和删除文件：SQLite 事务不能覆盖 Windows 文件系统，仍不能提供真正的跨资源原子性；采用提交后事件与清理队列。
- 删除任务时同步失败就回滚任务：删除文件失败不等于数据库删除失败，回滚会使用户无法完成任务删除；采用后处理清理和有限重试。
- 启动后持续扫描附件目录：会增加隐私、性能和文件占用风险，也超出 FR-ATT-006 的一次性诊断要求；拒绝。

## Consequences

### Positive

- 业务用例、元数据持久化和可替换文件存储保持清晰边界。
- 源文件安全；临时文件、原子移动、事务和队列覆盖导入失败与删除失败的主要不一致窗口。
- 数据库备份能力的范围不会被误读，后续备份/恢复实现有明确输入和一致性要求。

### Trade-offs and risks

- 文件和元数据仍不是跨资源的单一原子提交；补偿队列与启动诊断只能收敛不一致，不能替代完整备份。
- 进程在原子移动和元数据提交之间崩溃时，可能留下待诊断孤儿；系统不会在启动时擅自删除它。
- 任务删除后的清理依赖 `TaskDeleted` 事件订阅和后续有限重试；队列自身不可用时需要诊断日志和人工恢复。
- 当前备份范围尚未实现，后续备份任务必须在本边界上增加验证和恢复测试。

## Validation plan and evidence

DEV-070 使用仓库随附 .NET SDK 10.0.100 执行 Release build、Application/Infrastructure/Presentation/Architecture 相关测试和 `git diff --check`。关键证据覆盖中文、空格、长文件名、同名文件、源文件保持、复制途中失败、数据库失败补偿、路径穿越、打开/定位/重命名/移除、任务删除队列重试和任务编辑器逐个导入。WPF 窗口启动/关闭仍需在可观测 Windows 桌面上人工复测。

## Revisit criteria

若后续引入正式备份/恢复、云同步、跨设备附件迁移，或需要在导入和元数据之间提供更强的一致性保证，应以新 ADR 重新定义备份快照、加密、冲突和恢复协议；不得仅修改本 ADR 的实现细节来扩大备份范围。
