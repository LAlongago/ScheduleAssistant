## 关键设计选择与公共 API

### TaskItem

- `TaskItem.Create(...)` 创建普通 `Pending` 任务，版本固定为 `1`，`CreatedAtUtc` 与 `UpdatedAtUtc` 初始相同；未传优先级的重载使用 `TaskPriority.Normal`。
- `TaskItem.Rehydrate(...)` 是 DEV-020 的持久化重建入口，可恢复 ID、状态、完成时间、时间字段和版本，但仍验证全部不变量，不重放创建/完成行为。
- `UpdateDetails(...)` 先验证完整候选状态和更新时间，再一次性提交；不能编辑 ID、创建时间、周期身份、工作流状态或版本。
- `StartProcessing(...)`：`Pending -> InProgress`；重复开始是 no-op；`Completed` 必须先取消完成。
- `Complete(...)`：从未完成状态进入 `Completed` 并保存调用方时间；重复完成是 no-op，保留首次 `CompletedAtUtc`。
- `CancelCompletion(...)`：`Completed -> Pending`，清空完成时间，不恢复之前的 `InProgress`；对非完成状态是 no-op。
- `MarkAsOccurrenceOverride(...)` 只标记当前周期实例，不修改系列或其他实例。

### 其他实体

- `Category.Create/Rehydrate/UpdateDetails` 保存名称、颜色、排序、内置/归档标记、UTC 时间戳和版本。颜色规范为大写 `#RRGGBB`，名称去首尾空白后非空且最多 100 个 Unicode 标量值。
- `RecurrenceSeries.Create/Rehydrate/UpdateDetails` 保存共享字段快照和一个权威 `RecurrenceRule`。生效日期和时区只从 Rule 读取，不在 Series 重复存储。系列只保存计划墙钟时间，不猜测未冻结的 Deadline 模板偏移。
- `Reminder.Create/Rehydrate` 支持同一任务多个提醒节点。`RelativeOffsetMinutes` 约定为相对 Deadline 的分钟数：负数表示截止前，零表示到点，正数表示截止后。`MarkDelivered`、`MarkExpired`、`Cancel`、`MarkFailed` 只维护元数据状态，不发送通知或重试。
- `Attachment.Create/Rehydrate` 只保存元数据。管理路径规范化为 `/` 分隔的相对路径；拒绝绝对路径、UNC、驱动器前缀、路径遍历和 NUL，不检查真实文件系统。允许中文和空格显示名，大小必须非负。

### 值对象与纯规则

- `ZonedDeadline.CreateResolvedUtc(...)` 保留用户的 `LocalDate`、`LocalTime`、Windows `TimeZoneId` 和调用方已经解析的 UTC；非零偏移的 `DateTimeOffset` 明确规范化为零偏移。没有本地时间到 UTC 的转换 API。
- `RecurrenceRule` 只允许间隔 `1` 的每日、每周、每月和每年规则；查询窗口由 `OccurrenceDateCalculator.Calculate(...)` 按包含两端处理，并返回排序、去重后的 `IReadOnlyList<DateOnly>`。`CalculateOccurrences(...)` 提供 `OccurrenceDate` 包装结果。
- 月规则的 29/30/31 日在短月落到当月最后一天；年规则允许 2 月 29 日，非闰年落到 2 月 28 日；其他非法年月日组合被拒绝。
- `DisplayStatusCalculator.Calculate(task, nowUtc, todayLocal)` 严格执行 `Completed -> Overdue -> InProgress -> PlannedPast -> NotStarted`。
- `DeadlineUrgencyCalculator.Calculate(...)` 对无 Deadline 或已完成任务返回 `DeadlineUrgencyLevel.None`（数值 `-1`），不伪装成等级 `0`；等级 `0` 到 `4` 使用规格中的剩余时间边界。

## 时间、UTC 与版本职责

- Domain 不读取系统时钟、系统时区或本地日期。所有比较规则接收显式 `NowUtc`/`TodayLocal`。
- 所有绝对时间点都在入口规范化为 UTC `DateTimeOffset`；计划日期/发生日期保持 `DateOnly`，计划开始/结束保持本地 `TimeOnly`。
- `ZonedDeadline` 不解析 Windows 时区、不推算 DST 偏移、不自动修正无效或歧义墙钟时间；这些责任留给后续 Application 转换边界。
- 新建入口默认版本 `1`；重建入口恢复 `version >= 1`。DEV-010 的实体编辑不递增版本，避免与 Repository 双重递增；DEV-020 应在乐观并发提交成功时负责版本推进并通过重建入口恢复结果。
