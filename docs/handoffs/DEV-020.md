## 事务接口用法

Application 只依赖 `IPersistenceTransaction`，不接触 SQLite 类型。跨仓储写入示例：

```csharp
await using var transaction = await transactionFactory.BeginAsync(cancellationToken);
await taskRepository.AddAsync(task, transaction, cancellationToken);
await reminderRepository.AddAsync(reminder, transaction, cancellationToken);
await transaction.CommitAsync(cancellationToken);
```

仓储不共享连接；未传事务的写操作自行创建、提交或回滚短事务。更新成功返回 `PersistenceCommitResult<TEntity>`，其中实体是从提交行通过 `Rehydrate` 重建的版本。

## 迁移与编码约定

- 迁移文件位于 `Infrastructure/Persistence/Migrations`，作为嵌入资源，使用从 `001` 开始连续编号；已应用文件不可修改，只能追加新迁移。
- Guid 使用 `D` 格式文本；纯日期使用 `YYYY-MM-DD`；墙钟时间使用 `HH:mm:ss.fffffff`；UTC 使用固定 ISO 文本；DisplayStatus/Deadline 紧迫度不落库。
- Reminder 去重键全局唯一，同一任务可保存多个不同 key 的提醒；分类和系列引用采用 RESTRICT，任务删除仅级联提醒和附件元数据，保护周期历史。
- 本轮不解析时区或 DST，不推断系列 Deadline 模板，不管理 `settings`/`cleanup_queue`，不触碰附件文件。
