## 完成内容与设计

- 采用 `Microsoft.WindowsAppSDK 2.4.0`，实现 `WindowsNotificationService`，由正式 WPF 组合根注册为 `INotificationService`，并作为 hosted service 管理生命周期。
- 注册前订阅 `NotificationInvoked`；只有 `Register()` 成功后才报告通知能力可用。能力查询检查 API 支持状态、注册状态与 Windows `AppNotificationSetting`。注册/运行时失败和通知关闭返回安全诊断码。
- 正常 Stop 解除事件处理器并对成功注册的 manager 调用一次 `Unregister()`；普通退出不调用 `UnregisterAll()`。重复 Start/Stop 不重复注册或泄漏事件。
- 通知包含应用名、任务标题、Deadline 和剩余/逾期时间，以及“查看任务”按钮。XML 由 `XmlWriter` 生成以转义任务标题；激活解析只接受 `action=openTask`、规范 D 格式 `taskId`，拒绝未知字段及 URI、文件、命令等输入。
- 路由恢复主窗口并经 WPF Dispatcher 打开任务；初始化完成前收到的激活会排队。无效参数或已删除任务只打开主窗口。第二次业务启动只通知现有进程并退出，不初始化第二套数据库服务。
- ReminderScheduler 在 provider 不可用时保持休眠；发送失败后重新查询能力。若 Windows 通知在派发期间被关闭，提醒保持 Pending，且不被标记为 Failed、Delivered 或 Expired。
- 主机配置可用 `ScheduleAssistant:DataRoot`（环境变量 `ScheduleAssistant__DataRoot`）指定隔离数据目录；未设置时仍使用原用户 LocalApplicationData 默认路径。该配置用于本地隔离 smoke，不改变持久化模型。
