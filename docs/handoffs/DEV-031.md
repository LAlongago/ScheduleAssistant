## 完成内容与关键设计

- 新增 `ITaskQueries` 并由 `ITaskUseCases` 继承，提供指定日期、今天待处理、固定周历、固定 42 天月历、Deadline 分组和分页搜索查询。结果只暴露 `TaskDto`、只读 DTO 和 `ApplicationResult`。
- `CalendarEntry` 包含 `TaskDto`、`DisplayDate`、`IsPlannedOnDate`、`IsDeadlineOnDate`、Domain 派生的 `DisplayStatus` 和 `DeadlineUrgency`。
- 日历按 `(TaskId, DisplayDate)` 合并；同日计划/截止保留两个标记，异日分别出现，Deadline-only 保留，不按标题去重。Deadline 日历使用保存的 `ZonedDeadline.LocalDate`。
- 周历从周一到周日；月历从包含月首的周一开始连续 42 天，并为每格提供 `IsInDisplayedMonth`。日期条目按无计划时间、计划开始时间、优先级、Deadline、创建时间、ID 稳定排序；月历先按今日 Deadline/逾期、关键优先级、带时间计划、其他分组。
- 今天待处理只聚合未完成的历史计划、今日计划、今日本地 Deadline 和 UTC 已逾期任务；指定日期查询不会把历史待处理注入任意日期。每次查询只读取一次 `TimeProvider` 快照，状态和紧迫度复用 Domain 规则。
- Deadline 查询使用现有严格边界：`DeadlineUtc < now` 为逾期，恰好到点仍在 Upcoming；有限窗口支持 24 小时、3/7/30 天，All 包含逾期；已完成和无 Deadline 排除。
- 搜索覆盖标题、地点、具体事务、材料准备、备注；分类、优先级、工作流状态、是否逾期筛选在数据库执行。关键词作为字面子串，SQLite `LIKE` 的 `%`、`_` 和反斜杠均参数化并转义；空关键词查询全部任务。分页和总数复用同一筛选谓词，排序补充计划日期、计划时间、Deadline、优先级、创建时间和 ID。
