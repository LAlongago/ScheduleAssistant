## 完成内容与关键设计选择

- 新增独立 `IAttachmentUseCases`，并通过 `IAttachmentStore` 隔离文件系统；Presentation 只调用 Application 用例和 `ITaskEditorInteractionService`，不接触仓储、SQLite、文件系统或 Win32。
- 复用现有 `Attachment`、`IAttachmentRepository`、`IAppPaths.AttachmentsDirectory` 和 `cleanup_queue`。未修改既有迁移；仓储仅增加启动孤儿诊断所需的 `GetAllAsync`、显示名修改所需的 `UpdateDisplayNameAsync`。
- 导入路径固定为 `{task-id}/{attachment-id}_{safe-file-name}`。存储适配器支持中文、空格、长名称、同名文件和普通未知扩展名；清理非法字符、设备名、尾部空格/点并限制托管组件长度。每次解析都拒绝绝对路径、`..`、盘符/冒号、根目录外路径和链接目标越界。
- 导入先在同一任务目录创建临时文件，边复制边计算大小和 SHA-256；关闭并刷新临时文件后原子移动到最终路径，再在 SQLite 事务中提交元数据。数据库失败会删除已托管文件；补偿失败写入清理队列。源文件始终只读且不删除。
- 列表、打开、资源管理器定位、重命名显示名和确认移除均走独立附件用例。移除先提交元数据，再清理托管副本；失败返回非阻塞警告并入队。
- `TaskDeleted` 继续使用既有提交后事件，不修改 `TaskUseCases.DeleteAsync`。维护服务在事件后清理任务目录，失败入队；启动时最多读取 100 项、每项最多重试 3 次，然后做一次孤儿诊断，不注册定时器或持续扫描。
- 新建任务可先在编辑器中暂存所选文件；任务提交成功后按顺序逐个导入。单项失败保留任务、已成功附件和失败项，显示安全错误并允许再次保存重试；编辑已有任务初始化时加载附件列表。
- 日志只写维护操作、状态、计数和安全错误码，不写任务正文、附件内容或用户源文件完整路径。备份边界记录在 ADR-006：数据库备份不单独等价于附件字节备份，后续备份必须把数据库和托管目录作为一致性范围；源文件不属于应用托管/删除边界。
