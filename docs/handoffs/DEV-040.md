## 完成内容与关键设计选择

- 建立 `Resources/Theme.Light.xaml` 与 `Resources/Theme.Dark.xaml`，集中定义颜色/状态色、字体/字号、间距、圆角、边框和类型色条 token；`Resources/Controls.xaml` 提供按钮、文本框、复选框、导航项、卡片、焦点和禁用态样式。页面 XAML 使用资源引用，不散落颜色常量。
- `MainWindow` 采用固定宽度左导航、顶部标题/日期入口/搜索/新建入口、主内容和底部状态提示的三段式外壳；窗口最小尺寸为 `960×640`，应用只有一个由 DI 构造的主窗口。
- `NavigationService` 持有六个单例页面 ViewModel 并切换当前内容；`MainWindowViewModel` 只依赖 Presentation 导航服务和 `TimeProvider`，不访问仓储、SQLite、文件系统或 Windows API。`IWindowService` 只负责组合根显示已构造窗口。
- 六个页面均有独立 View/ViewModel：Today 使用明确标注的临时任务卡，Month 展示紧凑任务卡模式，其余页面显示明确的空/占位状态。可复用 `PageStatePresenter` 覆盖加载、空、错误和正常状态。
- `TaskCard` 预留完成勾选、标题、计划时间、Deadline、类型色条、优先级、地点和状态文本，并支持 Standard/Compact 两种密度；完成命令当前禁用，不复制 Domain/Application 规则。
- 修正任务卡地点文本 `Run` 对只读 `LocationText` 的绑定，显式使用 `OneWay`，避免 WPF 初始化阶段按默认双向绑定导致窗口启动异常。
- 根据人工冒烟截图移除折叠导航功能及其两处交互入口（顶部汉堡按钮、左下角折叠按钮），固定左侧栏宽度以保持导航图标和文字位置稳定。
- 搜索、新建任务、日期导航和完成勾选均是禁用/占位入口，不注册假的 `ITaskUseCases`、假仓储，也不写入数据库。`CommunityToolkit.Mvvm` 只按中央版本管理引用，未升级包。

- 初次按 `dotnet run --project .\src\ScheduleAssistant.Presentation\ScheduleAssistant.Presentation.csproj -c Release --no-build` 启动时复现了窗口未显示：WPF 在创建任务卡时对只读 `TaskCardViewModel.LocationText` 使用默认双向绑定，抛出 `InvalidOperationException` 并以 `-532462766` 退出；已在 Presentation XAML 中以最小改动修复。
- 修复后直接启动 Release 产物 `src/ScheduleAssistant.Presentation/bin/Release/net10.0-windows/ScheduleAssistant.exe`；3 秒后进程仍运行，`MainWindowHandle` 非零、标题为 `ScheduleAssistant`，随后通过正常关闭并清理测试进程。
- 移除折叠导航后再次启动 Release 产物；进程仍运行，`MainWindowHandle` 非零、标题为 `ScheduleAssistant`，随后通过正常关闭并清理测试进程。
