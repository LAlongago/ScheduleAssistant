## 完成内容与关键设计

- 新增 `TaskUseCases`/`ITaskUseCases`：普通任务创建、编辑、删除、完成、取消完成、开始处理；按 ID、计划日期、未来 Deadline 的基础查询；活动分类选项查询。
- 创建和换分类在事务内检查分类存在且未归档；编辑使用 Domain 的 `UpdateDetails`，保留 ID、创建时间和周期身份，不自动顺延计划日期。周期实例编辑/删除返回明确的后续用例错误。
- 所有业务绝对时间来自注入的 `TimeProvider` 并规范化 UTC；仓储返回的重建实体和新版本直接作为成功值，版本由仓储条件更新推进，冲突不覆盖。
- 新增 `ApplicationResult<T>`、安全错误模型和非阻断警告；错误区分 `Validation`、`NotFound`、`Conflict`、`StorageUnavailable`、`Unexpected`。取消通过 `OperationCanceledException` 传播，不映射为 `Unexpected`，不泄露 SQLite 类型或原始异常文本。
- 新增轻量 `InProcessEventBus` 和任务/提醒事件。事务提交后才发布；提交失败不发布成功事件；提交后事件失败或取消返回成功结果并设置 `RefreshRequired`。

## 提醒、事务与 Deadline 语义

- 创建带 Deadline 的未完成任务默认维护截止前 1 天的 Pending Reminder；编辑 Deadline 在同一事务内只条件取消 Pending 节点，再建立新的适用 Pending 节点，已 Delivered/Expired/Failed 节点不被覆盖；显式关闭提醒不会重新创建。
- 完成操作在同一事务内条件取消该任务仍为 Pending 的提醒，Delivered 节点保持原状态；取消完成根据已有取消节点的不同偏移恢复 Pending 计划，并按偏移去重。
- 为满足上述编排新增事务读取、按版本条件删除和 `CancelPendingByTaskIdAsync` 端口；SQLite 组合根通过 provider-neutral 映射适配器将 SQLite/IO 失败转换为 `PersistenceFailureException`，现有直接 Infrastructure 仓储测试仍保留原始约束验证。
- `DeadlineInput` 明确携带本地日期、墙钟时间和 Windows 时区 ID。唯一可解析时间保存本地输入、时区和 UTC；早于计划日期只返回 `Deadline.BeforePlannedDate` 警告。无效 DST 时间返回需修改，歧义时间必须提供匹配有效偏移的 `ConfirmedUtc`，不自动平移、不自动选择偏移、不写入未经确认的 Deadline。
